# Spravochnik EPB — Design Document

Внутренняя многопользовательская информационная система экспертной организации для ведения договоров, экспертиз промышленной безопасности (ЭПБ), ОПО, технических устройств, зданий/сооружений, задач, нормативно-технической документации и взаимодействия с Ростехнадзором. Сервер внутри организации, доступ по LAN.

Документ фиксирует визуальный язык и UX-паттерны, на которых строится весь интерфейс.

---

## 1. Технологический фундамент

| Слой | Решение |

### 3.3. Индикаторы сроков

Три токена `--deadline-ok / --soon / --overdue` (зелёный / оранжевый / красный). Используются в чипах `DeadlineChip` и цветной левой границе (`border-l-2`) у строк списков.

### 3.4. Типографика

- **Geist Sans** — основной шрифт (`font-sans`, через переменную `--font-geist-sans`).
- **Geist Mono** — моноширинный (номера экспертиз, договоров, штрих-коды).
- Заголовки: `text-2xl font-semibold tracking-tight` (дашборд), `text-base font-medium` (заголовки карточек).
- Подписи: `text-xs text-muted-foreground` (вторичная информация).
- UPPERCASE-tracking-wide (`text-[10px]/[11px]`) — для лейблов типа «ЭКСПЕРТИЗ», «КОНТРАКТ», категорий в фильтрах.

### 3.5. Радиусы и тени

- Базовый радиус `--radius: 0.5rem`.
- Карточки `Card` — `rounded-lg`, `border-border/70`, при hover (если ссылка) `border-primary/40 + bg-accent/30`.
- Чарты-контейнеры — `rounded-md`, без явной границы (фон `card`).

## 4. Главная страница — Дашборд (`src/app/page.tsx`)

Структура сверху вниз:

```
┌─────────────────────────────────────────────────────────┐
│ DashboardHeader                                        │
│  "Добрый день, Алексей"  + дата + кнопки действий     │
├─────────────────────────────────────────────────────────┤
│ KPI-полоса (4 карточки, 1×4 на xl, 1×2 на sm)          │
├─────────────────────────────────────────────────────────┤
│ Чарты (2 колонки на lg, 1 на мобильном)                │
│  • Экспертизы по статусам (donut)                      │
│  • Документы по сроку действия (горизонтальные бары)   │
├─────────────────────────────────────────────────────────┤
│ Списки (3 колонки на lg)                              │
│  • Мои задачи        • Ближайшие сроки  • Активность  │
├─────────────────────────────────────────────────────────┤
│ Загрузка сотрудников (2/3) + Контроль РТН (1/3)       │
└─────────────────────────────────────────────────────────┘
```

### 4.1. DashboardHeader

- Приветствие по времени суток: «Доброе утро / день / вечер / ночи» (`DashboardHeader` рендерит стабильный fallback «Здравствуйте» до монтирования — иначе hydration mismatch).
- Имя — первое имя пользователя (`currentUser`).
- Под ним — дата прописью (`ru-RU`), `capitalize`.
- Справа — кнопки:
  - `outline` «Новая задача» (`ListTodo`) → `/tasks?new=1`.
  - `primary` «Создать» (`Plus`) → dropdown с тремя пунктами: Договор, Экспертиза, Организация. Каждый пункт ведёт на соответствующий список с `?new=1`.

### 4.2. KPI-карточки

4 штуки, тоны: `default / warning / danger / success` (`KpiCard`):

| Метрика | Иконка | Тон | href | Подсказка |
| --- | --- | --- | --- | --- |
| Активные договоры | `FileText` | `default` | `/contracts` | сумма в `formatMoneyShort`, ссылка «Открыть» |
| Экспертизы в работе | `ShieldCheck` | `default` | `/expertise` | «N завершено за квартал» |
| Мои задачи сегодня | `ListTodo` | `default` | `/tasks` | просроченные, если есть — красным |
| Документы с истёкшим сроком | `FileX2` | `danger` если > 0, иначе `default` | `/expertise` | «Заключения ЭПБ, у которых истёк срок следующего контроля — требуется повторная экспертиза» |

**Визуал карточки:**
- Лейбл — uppercase-tracked, `text-xs text-muted-foreground`.
- Значение — `text-2xl font-semibold tracking-tight text-foreground`.
- Иконка — справа в квадрате `h-10 w-10 rounded-lg`, тонированная подложка `bg-{tone}/10 text-{tone}-600/dark-400`.
- Внизу — `hint` слева, кнопка-стрелка «Открыть» (`ArrowRight`) справа.
- При наличии `href` — вся карточка становится ссылкой, hover подсвечивает бордер и фон.

### 4.3. Чарты

**Экспертизы по статусам** (`ExpertiseDonut`):
- Donut `innerRadius=56, outerRadius=84`, `paddingAngle=2`, `stroke="hsl(var(--background))"` — кольца «отделены» друг от друга и от фона карточки.
- В центре — общее число экспертиз + подпись «экспертиз» uppercase.
- Справа — легенда: цветной квадратик + название + абсолютное значение + процент.
- При наведении на сегмент — кастомный `Tooltip` с абсолютным числом и процентом.
- Под чартом — итоговая строка: «Из N экспертиз M зарегистрированы в РТН».
- `isAnimationActive={false}` — устраняет «прыжок» при первом монтировании.

**Документы по сроку действия** (`DocumentStatusChart`):
- Горизонтальные бары (`layout="vertical"`), `barSize=20`, `radius=[4,4,4,4]`, `barCategoryGap=10`.
- Метки оси Y — 11px, `text-muted-foreground`, ширина 168px.
- Справа от каждого бара — числовая подпись через `<LabelList position="right">` (если значение > 0).
- Под чартом — итог: «Всего **N** документов · требуют внимания сейчас **M**».

### 4.4. Списки

**«Мои задачи»** (`MyTasksList`):
- Сортировка: сначала просроченные, потом по возрастанию длины приоритета (срочный → обычный).
- Чекбокс слева (`role="checkbox" aria-checked`) — локальный `useState<Set<string>>`, при отметке текст зачёркивается, строка приглушается до `opacity-60`.
- Счётчик «**X** из Y выполнено сегодня» в заголовке обновляется на лету.
- Просроченные строки — красная левая граница `border-l-deadline-overdue`, выполненные — прозрачная.
- В строке: моноширинный номер экспертизы · `DeadlineChip` без иконки · `PriorityBadge`.

**«Ближайшие сроки»** (`ExpiringSoon`):
- Заголовок «Ближайшие сроки · На 14 дней вперёд», ссылка «Календарь» в шапке.
- Фильтр-переключатель `ToggleGroup` (outline, sm): **Все · Экспертизы · Договоры · ТУ**.
- Каждая строка — `Link` с цветной левой границей по severity:
  - `urgent` → `border-l-deadline-overdue` (красный)
  - `warning` → `border-l-deadline-soon` (оранжевый)
  - `info` → `border-l-deadline-ok` (зелёный)
- Внутри: тип (`Экспертиза / Договор / Техническое устройство`) в маленьком чипе, номер договора моноширинным, `DeadlineChip` справа.
- Пустое состояние при пустом фильтре: «Нет событий в выбранной категории».

**«Последняя активность»** (`RecentActivity`):
- Лента событий с цветной точкой-индикатором слева (тип: `status/create/reject/doc/comment/task`).
- Текст + `at` в относительном формате (через `mounted`-флаг).

### 4.5. Загрузка сотрудников + Контроль РТН

- `EmployeeLoad` — горизонтальные сгруппированные бары по сотрудникам (open + done) с аватарами-инициалами.
- Правая колонка — текущие экспертизы на рассмотрении в РТН (severity + срок).

## 7. Архитектурные принципы

### 7.1. Серверные компоненты по умолчанию

`page.tsx` остаётся Server Component. Клиентскими делаются только:
- Компоненты с состоянием/эффектами (`DashboardHeader`, `DeadlineChip`, `MyTasksList`, `ExpiringSoon`, чарты).
- `TopBar`, `NavSidebar`, `CommandSearch`, `NotificationsPopover`, `UserMenu`, `ThemeToggle` — всё, что зависит от `usePathname` / клиентского состояния темы.

### 7.2. Hydration safety

Любой компонент, использующий `new Date()` или зависящий от текущего времени (`DashboardHeader`, `DeadlineChip`, относительные даты в `RecentActivity`), переводится в `"use client"` и использует паттерн:

```ts
const [mounted, setMounted] = useState(false);
useEffect(() => setMounted(true), []);
if (!mounted) return <StableFallback />;
```

Так первый серверный рендер и клиентская гидрация дают идентичный DOM.

### 7.3. Данные — пока моки

`src/lib/mock-data.ts` — единый источник правды для UI. Распределения, зависящие от дат (`documentValidityDistribution`, `dashboardKpis.documentsExpired`), считаются IIFE при загрузке модуля после объявления `parseRuDate` и `todayMidnight`. Целевой слой — Prisma + in-memory store `src/lib/db/store.ts`.

### 7.4. БЭ/БД — не выбран

PostgreSQL vs SQLite vs MSSQL — открытый вопрос. До выбора архитектура продолжает строиться на моках + Server Actions.

## 9. UX-инварианты

1. **Цвет — не единственный сигнал.** У статусов есть текстовая метка и цветная точка, у дедлайнов — иконка (`AlertTriangle / Clock / CalendarClock`). Это сохраняет читаемость при дальтонизме и в монохромной печати.
2. **Hover-состояния карточек** — `border-primary/40 + bg-accent/30`, всегда с курсором-указателем (`<Link>` оборачивает весь блок).
3. **Пустые состояния** — дружелюбные заглушки вместо пустого списка («Нет событий в выбранной категории»).
4. **Числа в моноширинном** — `tabular-nums` для всех счётчиков и долей, чтобы колонки цифр выравнивались.
5. **Заголовки карточек не дублируют оси чартов.** Ось Y у баров и заголовок — разные сущности, не повторяются.
6. **Кликабельная зона задач разделена.** Чекбокс и тело ссылки — разные `<button>` и `<Link>`, клик по чекбоксу не открывает карточку.
7. **`use client` ровно там, где нужно.** Дашборд остаётся пререндеренным статически — клиентский JS только в интерактивных узлах.
